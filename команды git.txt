УДАЛЁННЫЙ РЕПОЗИТОРИЙ

git push - загружает изменения из локального репозитория на репозиторий серва
git pull - обратное действие

git clone <URL> - клонирование локального репозитория с серва

ORIGIN - это имя удадённого репозитория по умолчанию. Тоесть при клонировании создаётся связь и записывается имя в ORIGIN
(после скачивании ветки будет не видно локально остальных веток находящихся в удалённом репозитории по команде git branch, для этого нужно команду git branch -a и после чего можно перейти на любую ветку командой git checkout <branch name>)

СВЯЗЬ ЧУЩЕСТВУЮЩЕГО ЛОКАЛЬНОГО РЕПОЗИТОРИЯ С УДАЛЁННЫМ

git remote add origin <url> подключение удалённого репозитория, при условии, что он там создан (на gitHub или gitLab или bitBucked) origin может быть любое имя, обычно остаётся origin

При первой связи репозиториев из локальной в удплённую нужно связать ветки

git push -u origin <branch>(тут говорится что например из текущей ветки main в сервер под названием ORIGIN в ветку с названием <branch>)
после связывания веток можно просто обновлять командой git push
не забудь указать токен, заранее созданный и настроеный

git remote -посмотреть принодлежность к удалённому серверу
git remote -v - проверить настройки удалённого сервера

Посмотреть как локальная ветка master связана с удалённой веткой master
git branch -vv
